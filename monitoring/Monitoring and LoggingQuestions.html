Tracing & CloudWatch Dashboards

  • CloudWatch Logs Insights: Uses a piped syntax (filter status='error' | stats count() by requestId). Can query up to 50 log groups concurrently to trace cross-service requests.
  • CloudWatch Metric Filters: Translates raw text patterns (e.g., "Authentication failed") or JSON variables into a continuous numerical metric for triggering alarms/dashboards.
  • AWS X-Ray: Visualizes end-to-end request paths. A 5xx error is a Fault (Red), 4xx is an Error (Yellow), and 429 Throttle is also a Fault.
  • ECS X-Ray Daemon: Runs on UDP Port 2000. In ECS, run it as a sidecar container in your task definition.

Centralized Logging & Archival

  • Cross-Account Subscriptions: Sending logs from multi-account environments to a central account requires an Amazon Kinesis Data Stream or Firehose as the recipient target.
  • Long-term Metric Archival: CloudWatch Metrics expire after 15 months. To keep them for 7 years, use CloudWatch Metric Streams pushing to S3 via Kinesis Firehose.
  • In-flight Log Transformations: To add metadata to logs before they hit S3, stream them through Amazon Kinesis Data Firehose with an AWS Lambda transformer.
  • CloudTrail File Integrity: Uses SHA-256 and RSA signature digest files dropped directly into S3. Use aws cloudtrail validate-logs to ensure non-repudiation.

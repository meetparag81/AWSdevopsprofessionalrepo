CloudFormation & AWS CDK

  • StackSets: Use to deploy identical templates across multiple accounts and regions. Service-managed permissions automatically deploy to new accounts joining an AWS Organization.
  • Custom Resources: Used to provision resources not natively supported by CloudFormation (e.g., executing a database migration schema or calling a third-party API). Backed by AWS Lambda or SNS.
  • Cross-Stack References: Stack A uses Export: in the Outputs section. Stack B uses Fn::ImportValue to retrieve it. You cannot delete or modify the exported value in Stack A while Stack B references it.
  • AWS CDK: Allows defining IaC using familiar languages (Python, TypeScript). The cdk synth command converts the code into a standard CloudFormation JSON/YAML template.

SSM, Service Catalog & AppConfig

  • SSM State Manager: Ensures EC2 instances remain in a desired configuration state (e.g., ensuring an antivirus agent is always running or a specific port is closed).
  • AWS Service Catalog: Allows central IT to create a "Portfolio" of approved CloudFormation templates ("Products"). Use Launch Constraints to dictate which IAM role the product assumes during deployment, abstracting permissions from the user.
  • AWS AppConfig: Used for managing dynamic feature flags and configuration data at runtime without redeploying application code. Supports native validation using Lambda before deploying the config.

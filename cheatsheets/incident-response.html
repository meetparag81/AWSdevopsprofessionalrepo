Master Cheat Sheet: Incident & Event Response

1. Core Services & Analogies

1. AWS Systems Manager (SSM) Incident Manager

Function: The central incident response hub for managing the "people" side of an outage. Handles on-call schedules, SMS/Voice paging, and escalation paths.

Why it's used: To automatically notify engineers, track acknowledgments, and escalate to a backup engineer if the primary contact misses the alert, while simultaneously triggering mitigation runbooks.

Simple Example: The 911 Dispatcher. It tracks who is on shift, sends the page, waits 15 minutes, and calls the backup if no one answers.

Exam Keywords: predefined escalation path page secondary engineer acknowledge alert SMS and voice call

2. AWS Config

Function: Records resource configuration changes and continuously evaluates them against compliance rules.

Why it's used: To audit historical resource states, enforce compliance (e.g., ensuring EBS volumes are encrypted), and trigger automated remediations via SSM.

Simple Example: The Security Camera & Auto-Lock. Takes a snapshot every time someone changes a setting. If a DB is made public, Config detects it and triggers a script to lock it back down.

Exam Keywords: compliance breaches evaluate configuration auto-remediation Config Aggregator

3. Amazon EventBridge (CloudWatch Events)

Function: A serverless event bus that routes state changes and API calls to specific targets.

Why it's used: To build event-driven architectures, route alerts across different AWS accounts seamlessly, and trigger actions based on specific payload patterns.

Simple Example: The Central Post Office. GuardDuty detects a threat and sends it to EventBridge. EventBridge reads the "zip code" (event pattern) and routes it to a delivery truck (Lambda).

Exam Keywords: event pattern cross-account event routing trigger a Lambda resource-based policy

4. AWS CloudTrail

Function: Records AWS Management API calls and user activity across the account.

Why it's used: For security auditing to know exactly who made an API call, what IP they used, and when they did it. Best enforced via Organization Trails.

Simple Example: The Itemized Credit Card Bill. If an EC2 server is mysteriously deleted, CloudTrail tells you exactly which user clicked 'Delete', at what time, and from which IP.

Exam Keywords: API activity audit trail who deleted/created Organization Trail

5. Amazon CloudWatch Synthetics

Function: Outside-in monitoring using programmable scripts (canaries).

Why it's used: To actively simulate complex user workflows (logging in, clicking carts) and capture visual evidence if the UI or endpoint fails.

Simple Example: The Mystery Shopper. A robot opens a browser, navigates to your site, and tries to check out. If broken, it takes a screenshot and alerts you.

Exam Keywords: simulate complex workflows capture screenshot canaries proactively monitor

6. Amazon CloudWatch Container Insights

Function: Automated performance monitoring for containerized applications.

Why it's used: To extract CPU, memory, and network metrics at the task/container level without custom agents, especially for serverless AWS Fargate.

Simple Example: The Rental Fleet Dashboard. Automatically gathers telemetry from every single Fargate container into one central dashboard without opening their hoods.

Exam Keywords: container-level metrics ECS cluster AWS Fargate EKS performance

7. Amazon GuardDuty

Function: Intelligent threat detection service using machine learning.

Why it's used: To continuously monitor network traffic, DNS logs, and CloudTrail for malicious activity, compromised credentials, and anomalous IAM behavior.

Simple Example: The Intelligent Security Guard. Flags if a server suddenly starts communicating with a known bitcoin mining IP address.

Exam Keywords: unauthorized access anomalous IAM behavior threat detection finding severity

8. Amazon Macie

Function: Data security service specifically for Amazon S3.

Why it's used: To automatically scan the inside of S3 objects and alert the security team if sensitive regulatory data is exposed.

Simple Example: The Highly Trained Auditor. Reads through S3 documents and alerts you if someone accidentally uploaded an Excel sheet full of SSNs.

Exam Keywords: Personally Identifiable Information (PII) credit card / SSN S3 data discovery

9. AWS Security Hub

Function: Cloud security posture management and alert aggregation.

Why it's used: To provide a single compliance score against industry frameworks and centralize security alerts from GuardDuty, Macie, and Inspector.

Simple Example: The School Report Card. Grades your cloud against standards (like CIS) and gives an overall score with a list of failing grades to fix.

Exam Keywords: Center for Internet Security (CIS) compliance score Foundations Benchmark

10. Amazon OpenSearch Service

Function: Managed search and analytics suite.

Why it's used: For high-speed, full-text log querying. Supports publishing internal diagnostic logs to CloudWatch to track down heavy queries.

Simple Example: The Lightning-Fast Library Catalog. Pour millions of logs in, instantly search for "Error". Use "slow logs" to track slow searches.

Exam Keywords: slow log publishing complex queries timing out

2. AWS Systems Manager (SSM) Deep Dive

Run Command

Execute on-demand commands across fleets without SSH/RDP. Provides granular IAM tracking and bulk concurrent execution controls.

State Manager

Continuous configuration compliance (anti-drift). E.g., repeatedly applying Ansible playbooks to ensure firewall rules remain intact.

Automation

Multi-step operational workflows. The standard target for EventBridge, Config auto-remediations, and CloudWatch Alarms. Requires an AssumeRole.

Session Manager

Browser/CLI secure interactive shell access. Eliminates bastion hosts. Logs everything immutably to S3/CloudWatch via KMS.

Patch Manager

Automate OS and security updates across fleets using Patch Baselines, approval delays, and strict Maintenance Windows.

Parameter Store

Cost-effective hierarchical key-value storage for config values and KMS encrypted SecureStrings. Cheaper alternative to Secrets Manager.

💡 3. Pro-Tips / Exam Scenarios (All 30 Key Takeaways)

Orchestration & Automation

  • Incident Manager Escalation: Native tool to create a predefined path to automatically page a secondary engineer if the primary misses an alert.
  • Step Functions .sync vs .waitForTaskToken: Use .sync when calling an SSM Automation document so Step Functions inherently pauses and waits. (SSM doesn't natively callback with a token).
  • Step Functions API Throttling: Don't write custom Lambda sleep loops for 503 errors. Use native ASL Retry and Catch blocks for exponential backoff.
  • Automated Thread Dump & Reboot: Avoid Lambda SSH. Configure the CloudWatch Alarm Action to directly trigger an SSM Automation document.
  • Config Auto-remediation AccessDenied: If an SSM execution triggered by Config fails, it means the SSM document's AssumeRole lacks IAM permissions to modify the target AWS resource.
  • S3 Bucket Made Public: Use AWS Config to detect the breach and automatically trigger the AWS-ConfigureS3BucketPublicAccessBlock SSM document.
  • Disk Full (No SSH): Trigger an SSM Run Command natively via a CloudWatch Alarm action to run a cleanup script directly on the instance OS.

Event Routing (EventBridge)

  • EventBridge DLQs: If EventBridge fails to deliver an event (e.g., Lambda is throttling), capture the lost event by attaching an SQS Dead-Letter Queue directly to the target.
  • EventBridge Cross-Account Routing: Attach a Resource-Based Policy to the central Event Bus granting events:PutEvents to the entire AWS Organization.
  • CloudFormation Stuck Rollbacks: Monitor for CloudFormation Stack Status Change events (where status is UPDATE_ROLLBACK_FAILED) globally via EventBridge.
  • AWS Scheduled Hardware Maintenance: Intercept maintenance notices seamlessly via an EventBridge rule matching the aws.health source.
  • Regional Network Degradation: Trigger regional failover runbooks using an EventBridge rule listening for aws.health and the AWS_EC2_OPERATIONAL_ISSUE code.
  • Security Hub Automation: Route Security Hub Findings - Imported events via EventBridge to Step Functions for automated isolation/notification.
  • Secrets Manager Rotation Failed: Capture the explicit RotationFailed event via EventBridge and route to SNS.

Forensics & Diagnostics

  • Isolating Compromised Instances: Never terminate or stop a compromised EC2 instance (it destroys volatile RAM). Apply a restrictive Forensic Security Group instead.
  • ASG Lifecycle Hooks for Forensics: Use the autoscaling:EC2_INSTANCE_TERMINATING hook to pause an instance. Trigger an EventBridge -> SSM Automation to pull logs, then signal the ASG to continue termination.
  • ECS/Fargate OOM crash: Capture the ECS Task State Change event via EventBridge. The payload contains the critical stoppedReason for diagnostic alerting.
  • CloudTrail Integrity: To definitively prove logs weren't tampered with by an attacker, enable Log File Integrity Validation (generates SHA-256 hashes & digital signatures).
  • Missing S3 GetObject Audits: By default, CloudTrail only logs Management Events. To audit file access, you must explicitly enable S3 Data Events.

Monitoring & Data Analytics

  • DynamoDB PITR Restoration: PITR always restores to a brand new table. You cannot overwrite a live table. You must write a custom script to scan the new table and insert missing items back into production.
  • Athena for S3 Logs: For instantaneous queries during a volumetric DDoS attack, use Amazon Athena to query ALB Access Logs directly in S3.
  • Fastest Query for JSON CW Logs: Use CloudWatch Logs Insights to interactively bin/filter logs already sitting in CloudWatch without exporting them.
  • Variable Traffic False Positives: Replace static CPU thresholds with CloudWatch Anomaly Detection to baseline normal historical ML patterns.
  • CloudWatch Metric Math (Ratios): Use Metric Math to dynamically calculate error percentages (e.g., divide `HTTPCode_ELB_5XX_Count` by `RequestCount`) and alarm on the result.
  • Cross-Region Dashboards & Alarms: Centralize alerting using CloudWatch Metric Math cross-region expressions (e.g., SEARCH queries targeting eu-west-1 from us-east-1).
  • Synthetics Canary Alerts: Bind a CloudWatch Alarm directly to the Canary's SuccessPercent metric, which can trigger an Incident Manager Response Plan.
  • Interactive Logs for EC2: The most native way to stream massive log files for near real-time querying is installing the unified CloudWatch agent and querying via Logs Insights.
  • Elastic Beanstalk Logs (Blocked SSH): If port 22 is blocked, use the Elastic Beanstalk console or EB CLI to request Snapshot Logs natively.
  • RDS Multi-AZ Failover Alerts: Do not rely on CloudTrail or connection metrics. Create a native Amazon RDS Event Subscription for the 'failover' category targeting SNS.
  • Lambda Timeout on External API: If a downstream API is slow, increase the Lambda execution timeout setting. Changing concurrency limits or memory will not fix synchronous latency.

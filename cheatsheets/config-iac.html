Master Cheat Sheet: Config Management & IaC (All 50 Qs)

1. Programmatic IaC (CDK & Catalog)

1. AWS CDK (Cloud Development Kit)

Function: Defines cloud infrastructure in code (Python, TypeScript) and compiles it down to CloudFormation.

Why it's used: To build reusable infrastructure (L3 constructs), enforce strict security rules via Aspects before deployment, and execute custom logic via AwsCustomResource.

Simple Example: The Architect's Blueprint Validator. Before building the house (deploying), `CDK Aspects` scan the blueprint to ensure no doors are missing locks (blocking wildcard IAM roles).

Exam Keywords: cdk diff CDK Aspects synthesis phase AwsCustomResource

2. AWS Service Catalog

Function: Centralized hub for creating and managing approved IT service catalogs.

Why it's used: To allow developers to safely launch pre-approved infrastructure across an AWS Organization without giving them direct administrative IAM permissions.

Simple Example: The Corporate Vending Machine. Developers push a button to get a pre-approved EC2 instance (Launch Constraint) without having the master keys to the AWS account.

Exam Keywords: Launch Constraints Delegated Administrator abstract IAM permissions

2. Systems Manager, Config & AppConfig

3. SSM State Manager

Function: Declarative, continuous configuration enforcement for EC2 and on-prem servers.

Why it's used: To natively enforce states (e.g., AD joins, running Ansible playbooks) avoiding fragile UserData scripts, and automatically fixing configuration drift.

Simple Example: The Relentless Hotel Maid. No matter how many times a guest messes up the room (drift), State Manager runs on a schedule to restore it to the exact standard.

Exam Keywords: continuous compliance enforce state AWS-ApplyAnsiblePlaybooks

4. AWS Config Auto-Remediation

Function: Links compliance auditing directly to automated fixes.

Why it's used: To detect non-compliant resources (like missing tags or open SGs) and instantly trigger native SSM Automation documents to fix them without writing Lambda scripts.

Simple Example: The Automated Traffic Cop. It spots a car speeding (untagged EC2), pulls it over, and automatically slaps a ticket on it (appends a tag via SSM).

Exam Keywords: auto-remediation SSM Automation document zero custom code

5. AWS AppConfig

Function: Dynamic configuration and feature flag management.

Why it's used: To roll out application changes gradually, monitor CloudWatch alarms during "bake time", and auto-rollback instantly without restarting compute environments.

Simple Example: The Volume Dial. Slowly turn up the volume of a new feature to 10%, 50%, then 100%. If the speakers crackle (CloudWatch Alarm), it instantly snaps back to 0%.

Exam Keywords: feature flags dynamic rollout no restart required

6. EC2 Image Builder

Function: Automates the creation, testing, and deployment of virtual machine images (AMIs).

Why it's used: To establish a secure, repeatable weekly pipeline for baking hardened OS images. Never poll this service; use it to push SNS events when a new AMI is ready.

Simple Example: The Factory Assembly Line. It takes a raw OS, installs your custom security software, runs a test suite on it, and publishes the finished "Golden Image" AMI.

Exam Keywords: Golden AMI event-driven pipeline automate image creation

3. CloudFormation Mechanics & StackSets

Stack Coupling & Naming

Nested vs Cross-Stack: Cross-Stack (Exports) creates a hard lock. You can't modify an exported value. Nested Stacks bypass this and overcome the 51,200-byte size limit.

Name Collisions: To deploy Dev and Prod stacks in the same account and region, completely remove explicit physical Name: properties to let CFN auto-generate unique hashes.

Secrets & Dynamic References

Secrets Manager: {{resolve:secretsmanager:...}} Use combined with SecretTargetAttachment to dynamically generate and auto-rotate RDS passwords.

SSM SecureString: {{resolve:ssm-secure:...}} Best for static encrypted keys that do not need automatic rotation functionality.

StackSets Orchestration

AccountRemovalBehavior: Set to RETAIN if you want an account moved out of an OU to keep its infrastructure intact instead of destroying it.

Drift Recovery: If someone manually deletes a resource in one member account, do NOT delete the stack instance. Execute UpdateStackInstances on that specific account.

Policies & Conditions

Stack Policy: Prevents specific resources from Update:Replace or Update:Delete during stack updates.

DeletionPolicy: Retain: Survives stack deletion entirely.

CreationPolicy: Pauses stack creation until OS scripts finish via cfn-signal.

🚨 Troubleshooting CloudFormation Failures

DELETE_IN_PROGRESS (Custom Resource Stuck): The backing Lambda was deleted out-of-band. Manually send a "Status": "SUCCESS" JSON payload via curl -X PUT to the S3 ResponseURL found in CloudTrail.

UPDATE_ROLLBACK_FAILED: A resource failed to revert. Fix the out-of-band issue (e.g., recreate the manually deleted IAM role it needs for teardown), then execute ContinueUpdateRollback.

S3 DELETE_FAILED: CloudFormation cannot delete an S3 bucket with objects inside it. It must be emptied first.

DependsOn Race Condition: If CFN fails saying a bucket doesn't exist when applying a bucket policy, explicitly add DependsOn: MyBucket to the policy resource to force sequential execution.

💡 4. Compute, CI/CD, & The Polling Trap

CI/CD & Compute Workflows

  • Private EKS Deployments: To run kubectl apply in CodePipeline against a private EKS cluster, you MUST attach the CodeBuild project to the private VPC subnet and map its IAM role into the Kubernetes aws-auth ConfigMap.
  • Least Privilege Pipeline Execution: To allow a developer to manually trigger a CodePipeline that uses CloudFormation (without giving the developer full admin access), grant the developer iam:PassRole so they can pass the Service Role to CFN.
  • Elastic Beanstalk AL2 Proxies: On Amazon Linux 2 platforms, NGINX configurations placed in .ebextensions are completely ignored. They MUST be placed in .platform/nginx/conf.d/.
  • Elastic Beanstalk Secrets: Do not place highly sensitive DB passwords in plain-text Environment Properties. Grant the EC2 instance profile access to Secrets Manager and fetch the secret via the AWS SDK at runtime.
  • EC2 Image Builder to Beanstalk: To auto-update Beanstalk with a new AMI, use an Event-Driven architecture (Image Builder -> SNS -> Lambda -> UpdateEnvironment API). Do not use .ebextensions for AMI swaps.

The "Polling" Anti-Pattern

The AWS DevOps Professional exam heavily penalizes architectures that rely on polling (e.g., writing custom bash loops to check an API every 5 minutes, or using Managed Updates to poll for AMIs).

When you see the word "poll": Instantly look for a distractor that uses EventBridge, Amazon SNS, or native AWS Config remediation actions. AWS strongly prefers asynchronous, event-driven, push-based architectures.

Avoid: Cron jobs Avoid: While loops Favor: EventBridge Favor: Native SSM triggers

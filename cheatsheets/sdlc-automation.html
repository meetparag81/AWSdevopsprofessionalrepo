Master Cheat Sheet: SDLC Automation

1. Core Services & Analogies

1. AWS CloudFormation

Function: Infrastructure as Code (IaC) templating and deployment service.

Why it's used: To automate infrastructure provisioning, prevent accidental deletion of stateful resources (Stack Policies), and deploy across multiple accounts/regions simultaneously (StackSets).

Simple Example: The Real Estate Blueprint. A Stack is the built house. A Stack Policy is the bodyguard standing outside your master bedroom (RDS database) preventing the contractor from bulldozing it during a remodel.

Exam Keywords: Update:Replace DeletionPolicy: Retain service-managed permissions Change Set parameter overrides

2. AWS CodeDeploy

Function: Automated application deployment service to Amazon EC2, AWS Fargate, and AWS Lambda.

Why it's used: To shift traffic safely (Canary/Linear deployments), execute scripts during deployment transitions (Lifecycle hooks), and automatically roll back to the last known good revision on failure.

Simple Example: The Two Houses. Blue/Green deployments are like buying a fully furnished new house (Green) while keeping the old one (Blue). You move in instantly, and if the plumbing breaks, you just drive back to the old house. No downtime.

Exam Keywords: BeforeAllowTraffic LambdaLinear10PercentEvery3Minutes Retain the content latest successful revision

3. AWS CodePipeline

Function: Fully managed continuous delivery service that automates release pipelines.

Why it's used: To orchestrate builds, enforce manual approval gates, integrate Step Functions for complex/long integration tests, and manage cross-region/cross-account deployments securely.

Simple Example: The Factory Conveyor Belt. It moves code from the warehouse to the assembly station (CodeBuild), pauses the belt completely for a manager's signature (Manual Approval), and then ships it (CodeDeploy).

Exam Keywords: Customer Managed KMS Key (CMK) cross-region actions Step Functions action Manual Approval

4. AWS CodeBuild

Function: Fully managed continuous integration service that compiles source code, runs tests, and produces software packages.

Why it's used: To run automated tests natively, cache large dependencies (like Maven or npm) in S3 to speed up build times, securely authenticate to ECR, and connect directly to private VPCs.

Simple Example: The Secure Factory. To deliver a package (Docker image) to a highly secure warehouse (ECR), the factory worker must first get a temporary VIP pass (aws ecr get-login-password) in the pre-build phase before pushing.

Exam Keywords: reports section S3 cache target VPC ID env: secrets-manager

5. AWS Serverless Application Model (SAM)

Function: Open-source framework used to build, test, and deploy serverless applications on AWS.

Why it's used: To define Lambda functions, API Gateways, and DynamoDB tables using shorthand syntax, and to easily package and upload deployment artifacts to S3 while rewriting template URIs.

Simple Example: The Kitchen & Shipping Dept. `sam build` is the prep cook gathering all ingredients. `sam package` is the shipping department zipping them up, putting them in an S3 warehouse, and generating your updated receipt (a new CloudFormation template).

Exam Keywords: sam build followed by sam package DeploymentPreference: Canary Traffic splitting

6. AWS CodeArtifact

Function: Fully managed artifact repository service designed to securely store and share software packages.

Why it's used: To allow internal development teams to consume semantic-versioned shared libraries and securely cache open-source dependencies pulled from the internet.

Simple Example: The Internal Library. Instead of every single developer downloading the same package from the public internet every time, CodeArtifact downloads it once, stores a secure copy in your AWS account, and serves it internally.

Exam Keywords: aws codeartifact login semantic versioned package cache open source packages

2. CodeDeploy Lifecycle Hooks (Strict Execution Order)

1. ApplicationStop

The very first hook. Used to gracefully shut down the currently running application (e.g., pm2 stop app or stopping Nginx) before anything else happens.

DownloadBundle (Native)

Not scriptable in appspec.yml. The CodeDeploy agent securely downloads the new revision files from Amazon S3 or GitHub to a temporary directory.

2. BeforeInstall

Execute pre-installation tasks. Commonly used to decrypt sensitive files, back up old directories, or run aws codeartifact login to prepare for dependencies.

Install (Native)

Not scriptable. The CodeDeploy agent copies the unzipped revision files from the temporary directory to their final destination on the instance.

3. AfterInstall

Configure the application and resolve dependencies. This is where you typically run npm install, pip install -r requirements.txt, or fix file permissions.

4. ApplicationStart & ValidateService

ApplicationStart: Starts the newly installed application process.
ValidateService: Runs tests to verify the application is healthy before passing the deployment.

💡 3. Pro-Tips / Exam Scenarios (Key Takeaways)

CodePipeline & Artifacts

  • Cross-Region Deployments: You must configure a local S3 artifact bucket in the destination region and encrypt the entire pipeline using a Customer Managed KMS Key (CMK).
  • Cross-Account CodePipeline: The pipeline in Account A must assume a cross-account IAM role in Account B. The artifact bucket must also use a CMK, as default AWS managed keys cannot be shared across accounts.
  • Manual Approvals + CloudFormation: To allow an architect to review infrastructure changes before deployment, sequence the actions as: Create Change Set -> Manual Approval -> Execute Change Set.
  • Enforcing PR Approvals: Do not use CodePipeline manual approvals to enforce GitHub/CodeCommit PR checks. Natively enforce this by attaching a CodeCommit Approval Rule Template requiring specific IAM group sign-offs.
  • Long Running Integration Tests: If a test takes hours and requires complex branching logic, use an AWS Step Functions action directly in CodePipeline instead of CodeBuild.

Deployment Strategies

  • ECS Blue/Green Data Validation: To run a test script against the new Green container before live customer traffic hits it, use the BeforeAllowTraffic hook in CodeDeploy.
  • Auto Scaling CodeDeploy Integration: If an ASG scales out, CodeDeploy natively intercepts the boot process and automatically deploys the latest successful revision before placing it in service.
  • Elastic Beanstalk Canary: The native way to shift fractional traffic (e.g., 15%) to a new version for a timed evaluation period is using the Traffic splitting deployment policy.
  • CodeDeploy Automatic Rollbacks: CodeDeploy does not "undo" steps or run rollback scripts. It simply initiates a brand new deployment using the last known good application revision.
  • Retaining Manual Hotfixes: By default, CodeDeploy deletes files not tracked in the previous deployment. To prevent wiping out manual hotfixes, choose the Retain the content deployment option.

CodeBuild & Testing

  • Slow Builds (Dependency Downloads): If CodeBuild takes 20 minutes downloading Maven/npm packages, dramatically speed it up by specifying an S3 cache path in the buildspec.yml file.
  • CodeBuild inside a VPC: To run integration tests against a private RDS database, you must configure the CodeBuild project with the VPC ID, private subnets, and Security Groups.
  • Visualizing Test Results: To see JUnit test pass/fail charts directly in the AWS Console, define a reports block in the buildspec.yml pointing to the XML files.
  • Secure Passwords in CodeBuild: Never pass passwords via CodePipeline environment variables (plaintext). Reference AWS Secrets Manager natively using the env: secrets-manager mapping in the buildspec.
  • Pushing to ECR: The IAM Service role needs ecr:GetAuthorizationToken permissions, and the buildspec must run aws ecr get-login-password piped to docker login in the pre_build phase.

Automation Security & Alerts

  • CodeGuru Security Review: Run Amazon CodeGuru in the Build Stage to fail the pipeline immediately if SAST vulnerabilities are detected, preventing buggy code from deploying.
  • Slack Notifications for CodeDeploy: Route native CodeDeploy deployment state-change events (Success/Fail) through Amazon EventBridge to trigger a Lambda function that posts to Slack.
  • CloudFormation Drift Detection Alerting: The lowest overhead way to alert on manual out-of-band changes to a stack is using AWS Config (cloudformation-stack-drift-detection-check) routed via EventBridge to SNS.
  • Pull Request Auto-Testing: When using CodeConnections to a Git repo, configure CodeBuild webhook filters for PR created/updated events to trigger unit tests natively on PRs.
